# 10_实测框架 —— 明天现场填这五张表

目标是**用同一套口径**把报告里 R1–R6 的预测值换成实测值。

## 0. 一分钟说明

| 文件 | 行数 | 对应要求 | 谁填 |
|---|---|---|---|
| `A_姿态.csv` | 6 | R1 放置方式：读码器固定在下，只改箱体哪个面朝下（B-BOTTOM / T-TOP / F-FRONT / F-BACK / S-LEFT / S-RIGHT） | 现场 1 人 + 相机 |
| `B_距离_9dBi.csv` | 24（4 位置 × 6 档） | R3 距离影响（9 dBi） | 现场 + `rfidmon` |

| `场地与标签.csv` | 7 项 | 全部 | 进现场第一件填它 |

## 1.1 A 表的六种"朝下面"（读码器不动）

| 编号 | 姿态 | 朝下的面 | 箱体立起高度 |
|---|---|---|---|
| A1 | 正立 | B-BOTTOM 底面 | 300 mm |
| A2 | 倒置 | T-TOP 顶面 | 300 mm |

> 测 A 组时**读码器不许移动**；只在箱子和读码器之间垫同样的高度档（建议 10 cm），
> 并在「备注」里记下箱体立起高度 —— 标签在箱内，距离是按立起高度/2 折算的。

## 2. 填写纪律（不遵守数据就废掉）

1. **每档 ≥30 秒、≥3 箱**；至少记 3 箱的“读全数/6”。
2. 照片**必须带面标**（`F-FRONT` / `F-BACK` 纸标），否则无法核对朝向。
3. 厂家 / 型号 / 天线增益 / 天线号 **一档都不能空**，否则归因无效。
4. 记环境：金属托盘、邻机读码器、人员走动。
5. 每换一次硬件，先确认 `SettingPrm.xml` 里的 IP 与功率档，再开始计时。
6. 测完执行 `rfid pause`（释放 LLRP 会话），否则产线软件停读 —— 已发生 5 次。

## 3. 判定口径（建议，评审确认后固化）

| 判定 | 阈值 |
|---|---|
| 读全 | 6/6，30 秒内全部读到且连续 3 箱成立 |
| 可用 | 平均 ≥5.4/6（90%），无箱低于 5/6 |
| 临界 | 平均 4.8–5.4/6，需调姿态或距离 |
| 不可用 | 平均 <4.8/6，或出现箱级 0 读 |

## 4. 填完之后

```bash
cd ../09_报告/_build

# 0) 先体检：哪张表填了几行、硬件标识有没有漏、判定落在哪一档（不出图）
python apply_measured.py --check

# 1) 出实测图 + 汇总（边测边跑，空单元自动跳过）
python apply_measured.py
#    → figs/fig7m_distance_measured.png、fig8m_vendor_measured.png、fig11m_variants_measured.png
#    → 09_报告/实测汇总.md（含每档「读全/可用/临界/不可用」判定）

# 2) 出幻灯片（PPT 里的图仍是预测版；实测版单独出，别把预测图当实测）
python make_ppt2.py
```

> **不要**把填好的 CSV 覆盖到 `_sim/`：`sim_model.py` 是**生成器**，一跑就把 `_sim/*.csv` 重新写回预测值，
> 覆盖掉的实测数据收不回来（`_sim/` 是"模型假设的输出"，实测值只留在本目录与 `figs/fig*m`）。
>
> 判定口径（上表）已写进 `apply_measured.py` 的 `VERDICT` 常量；要改档位就改那一处，汇总表跟着变。
>
> 空跑校验：`python apply_measured.py --tpl <某目录> --out <图目录> --summary <汇总.md>`，
> 可以拿一份填了假数据的副本先演练，不碰仓库里的图。
