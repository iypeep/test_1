# 架构与用法

## 1. 前提：算力只在办公机

机台没有到模型的通路，所以机台**不思考，只执行**：

- **办公机**：omp（或任何脚本）做判断 → `ctl\ompremote.py` 投任务
- **公盘 TBZ**：任务 / 实时输出 / 结果 / 文件，全部是普通文件
- **机台**：`bridge\omp-body.ps1` 认领任务、在本机执行、回写结果

```mermaid
sequenceDiagram
    participant Op as 办公机 ompremote.py
    participant Hub as TBZ\_omp\machines\<M>
    participant Body as 机台 omp-body.ps1
    participant Win as 机台 Windows

    Op->>Hub: inbox/<id>.job.json（+ files/<id>-x.ps1 或 push/<id>/…）
    Body->>Hub: 每 5s 扫 inbox
    Body->>Hub: 建 run/<id>.job.json.lock（认领，原子）
    Body->>Win: powershell -File task.ps1 （或 cmd / fetch / push / kill / omp）
    Win-->>Hub: run/<id>.stdout.txt、run/<id>.stderr.txt（运行中即时可读）
    Op->>Hub: 轮询 out/<id>.result.json，同时增量读 stdout/stderr
    Body->>Hub: out/<id>.result.json（status/exit/耗时/stderr 尾部）+ 产物
    Op->>Hub:（可选）inbox/<id>.cancel
    Body->>Win: taskkill /PID <child> /T /F
```

认领用"在 `run\` 下 `CreateNew` 建 `<id>.job.json.lock`"：同卷 SMB 上是原子的，
多台办公机同时投递也不会重复执行；job 文件本身随后被 `Move-Item` 挪进 `run\` 留档。

## 2. 任务种类

| kind | 输入 | 机台动作 | 产物 |
|---|---|---|---|
| `ps` | `file`（inbox\files 下的 .ps1）或 `code` | `powershell -NoProfile -ExecutionPolicy Bypass -File` | stdout/stderr + result |
| `cmd` | 同上（.cmd/.bat） | `call <脚本>` | 同上 |
| `fetch` | `patterns[]`、`max_mb` | 逐 glob 递归收集，流式拷到 `out\<id>.files\` | manifest.tsv（rel/size/sha1） |
| `push` | `inbox\push\<id>\<name>`、`target` | 拷到 target（必要时建目录），算 sha1 | result.written[] |
| `kill` | `pid` 或 `name` | `taskkill /T /F` | result |
| `ping` | — | 自述能力（PS/cmd/管理员/python/node/omp） | result.capabilities |
| `omp` | `prompt`、（`continue`/`model`/`max_time`/`mode`） | 跑本机 omp（**需要该机台有模型通路**） | stdout + result |

公共字段：`cwd`（工作目录，缺省安装目录）、`timeout`（秒，默认 900，到点树杀）、
`args`（追加给脚本的参数）、`env`（给脚本的环境变量）、`note`。

## 3. 状态机

| status | 含义 | 下一步 |
|---|---|---|
| `ok` | 退出码 0 | 读 stdout / 产物 |
| `error` | 退出码非 0 | `run\<id>.stderr.txt` 全文、`result.stderr_tail` |
| `timeout` | 超时被树杀 | 拆小任务或调大 `--timeout` |
| `canceled` | 收到 `.cancel` | — |
| `partial` | fetch 部分文件失败 | 看 manifest 里 `FAIL` 行（多为被独占/权限） |
| `empty` | fetch 一个都没匹配 | 检查 glob（`-Recurse` 默认开） |
| `bad_job` | JSON 解析失败/未知 kind/缺字段 | 检查写入方 |
| `no_omp` | `ask` 但机台没装 omp | 走 `run` 主路径，或装 omp |

## 4. 为什么脚本走文件而不是塞进 JSON

两个理由，都是实测踩过的：

1. **编码**：PS 5.1 读**无 BOM 的 UTF-8** 脚本会按 ANSI(GBK) 解释 → 中文变乱码甚至语法错
   （AnchorHub 契约 #85）。控制端落盘时统一补 BOM，脚本内容就与 JSON 转义、命令行转义
   彻底解耦。
2. **尺寸/可读性**：几百行的采集脚本塞进 JSON 字符串，出问题没法直接读。

`fetch` 的 manifest 也是同理：`rel<TAB>size<TAB>sha1`，办公机侧逐条复算 sha1 再落盘。

## 5. 部署与升级

```
deploy                  # bridge\*.ps1 + install.cmd + 现场操作卡 → <hub>\bundle
bootstrap <M>           # 借 AnchorHub 的 exec 在机台上 Start-Process 起安装器（-Silent）
```

`bootstrap` 的脚本只有 `Test-Path` + `Start-Process`，因此不触发 AnchorHub 的
写白名单/绝对禁止清单（`curl|Invoke-WebRequest|iex` 等在 safe/full 两档都拦）；真正
写文件的是被拉起来的 `install.ps1` 进程，它不在策略扫描范围内。

没有锚点的机台：把 `bundle\install.cmd` 弄过去双击一次即可（一分钟、免管理员）。
**重跑 install 就是升级**：它先杀掉旧进程再起新的，`bridge.lock` 防止双开。

## 6. 安全边界（务必按这个理解）

- 公盘 `machines\<M>\inbox` 的**写权限 = 机台上的执行权限**。公共盘上任何人能写，
  就能在装了 body 的机台上跑脚本。真正的边界是共享目录 ACL：要收紧就把
  `_omp\machines`（并给 `_omp\bundle` 只读）授权给专用账号。
- `stopall` 在公盘写 `policy\disabled.txt`，所有 body 立刻停止接新任务（正在跑的
  不打断，需要时用 `cancel`/`kill`）。这是止血开关。
- 机台侧有 `ALLOWED_CWD` 可选白名单：配了之后，job 的 `cwd` 越界会回落到安装目录。
- 审计：机台本地 `bridge.log`（ASCII，滚动 1MB）+ 公盘 `run\`/`out\` 的全部留档。

## 7. 故障排查

| 现象 | 判断 | 处理 |
|---|---|---|
| `machines` 里没这台 | body 没起 / 公盘不可达 / 机器没登录 | 机台上跑 `install.cmd`，看 `bridge.log` |
| 心跳有但任务不动 | 没认领 | 看 `run\` 里有没有 `.lock`；确认没被 `stopall` 暂停 |
| `error` 且 stderr 是乱码 | 脚本不是 UTF-8 BOM | 用 `run -f` 让控制端补 BOM |
| `fetch` 全是 `FAIL` | 文件被独占 | 机台上用 `run` 里 `[IO.File]::Open(...,'ReadWrite')` 共享读，或先停软件 |
| `fetch` 全是 `MISS` | glob 不对 | `run` 里先 `Get-ChildItem -Path 'D:\x' -Filter '*.log'` 探一下 |
| 任务偶发 2 倍延迟 | 桥轮询间隔 | `-PollSec` 调小（代价是公盘 IO） |
| 想确认是谁在跑 | `state\heartbeat.json` 有 user/pid | — |
